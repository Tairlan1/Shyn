# Атрибуция авторства: Doyle / Poe / Wells / London / Twain

Два файла:

- **`preprocess_corpus.py`** — очистка корпуса и нарезка на окна ~1500 слов.
- **`train_model.py`** — обучение модели атрибуции авторства и предсказание
  автора для нового текста. Импортирует `preprocess_corpus.py`, поэтому
  оба файла должны лежать в одной папке.

## Установка

```bash
pip install -r requirements.txt --break-system-packages   # если Linux/venv не используется
# опционально, для лучшей сегментации предложений:
python -c "import nltk; nltk.download('punkt'); nltk.download('punkt_tab')"
```

Без `nltk` скрипт тоже работает — включается устойчивый regex-сплиттер
предложений (чуть менее точный на редких синтаксических конструкциях).

## Шаг 1. Предобработка корпуса

Ожидаемая структура входных данных:

```
/data/ArthurConanDoyle/*.txt
/data/EdgarAllanPoe/*.txt
/data/H.G.Wells/*.txt
/data/JackLondon/*.txt
/data/MarkTwain/*.txt
```

Запуск:

```bash
python preprocess_corpus.py \
    --input-dir /data \
    --output-dir /data_processed \
    --target-words 1500 --min-words 1450 --max-words 1550
```

Что делает:

1. Удаляет шапку/подвал Project Gutenberg, "Produced by", лицензионный
   блок, метаданные (Title/Author/Release date/...).
2. Удаляет оглавление (Contents), Appendix/Index/Glossary/Footnotes,
   если они являются "хвостом" книги.
3. Вырезает сноски, вставки переводчика/редактора (`[Footnote ...]`,
   `[Translator's note: ...]`), нумерацию сносок `[12]`.
4. Чинит перенос слов по слогам на конце строки (типичный артефакт
   OCR/печатных изданий), склеивает строки одного абзаца, нормализует
   кавычки/тире.
5. Считает эвристический OCR-скор, долю частотных английских слов и
   другие метрики качества — результат в `quality_report.json`, книги
   с подозрительно низкими показателями отмечаются предупреждением.
6. Ищет дубликаты и почти-дубликаты книг (в т.ч. разные переиздания
   одного произведения) через шинглирование + коэффициент Жаккара —
   результат в `duplicates_report.json`.
7. Режет очищенный текст на окна 1450–1550 слов, не разрывая предложения
   и абзацы, отдавая приоритет границам глав и избегая начала/конца окна
   на реплике диалога.

Результат в `/data_processed/`:

```
dataset.jsonl            # основной ML-датасет: по одному чанку на строку
quality_report.json       # метрики качества по каждой книге
duplicates_report.json    # найденные дубликаты/почти-дубликаты
preprocessing.log         # подробный лог
```

**Перед шагом 2 обязательно просмотрите `quality_report.json` и
`preprocessing.log`** — если для какой-то книги слишком мало слов после
очистки или низкий OCR-скор, значит либо в неё затесался нестандартный
формат метаданных Gutenberg (стоит поправить файл вручную), либо это
реально повреждённый скан.

## Шаг 2. Обучение модели

```bash
python train_model.py train \
    --data /data_processed/dataset.jsonl \
    --model-dir ./model \
    --cv-folds 5 --test-size 0.15
```

Подход:

- **Признаки**: символьные n-граммы (2–5, TF-IDF) — основной сигнал
  индивидуального стиля; словарные n-граммы (1–2); явные стилометрические
  признаки (длина предложений и её вариативность, богатство словаря,
  частоты пунктуации, частоты ~200 служебных слов, доля диалога и т.д.).
- **Модель**: калиброванный стэкинг (LinearSVC + LogisticRegression + SGD)
  с логистической регрессией как метамоделью — даёт как точный класс, так
  и откалиброванную вероятность по каждому автору.
- **Валидация**: разбиение **по книгам** (`GroupShuffleSplit`/`GroupKFold`),
  а не по чанкам — иначе чанки одной и той же книги могли бы попасть и в
  train, и в test, и модель "запоминала" бы сюжет/лексику конкретного
  произведения вместо стиля автора. Итоговая метрика на отложенном тесте —
  честная оценка на **книгах, которые модель не видела при обучении**.
- В конце модель дообучается уже на 100% данных для продакшн-использования.

В консоли будут: метрики кросс-валидации, classification report и матрица
ошибок на отложенном тесте. Сохраняется:

```
model/author_style_pipeline.joblib
model/label_encoder.joblib
model/model_meta.json
```

## Шаг 3. Определение автора нового текста

```bash
python train_model.py predict --model-dir ./model --input unknown.txt
# или
python train_model.py predict --model-dir ./model --text "some raw text..." --json
checker

python train_model.py predict --model-dir "C:\Users\Tair\Desktop\Shyndyq\model" --input "C:\Users\Tair\Desktop\Shyndyq\data\Tairlan\Book_1.txt"

python train_model.py train --data "C:\Users\Tair\Desktop\Shyndyq\data_processed\dataset.jsonl" --model-dir "C:\Users\Tair\Desktop\Shyndyq\model" --cv-folds 5 --test-size 0.15
```       

Текст проходит через тот же пайплайн очистки и нарезки на окна ~1500 слов,
модель предсказывает вероятность по каждому окну, и они агрегируются
(геометрическое среднее вероятностей) в общий вердикт по всему тексту с
разбивкой по каждому отдельному окну — так видно, устойчив ли вывод модели
или на разные части текста она отвечает по-разному.

## Замечания по качеству/масштабированию

- Для 5 авторов эталонного уровня стоит ожидать порядка сотен-тысяч
  чанков суммарно (десятки произведений на автора) — этого достаточно для
  предложенной классической стилометрической модели; на таких объёмах
  она стабильно превосходит дообучение трансформеров "с нуля" и по
  качеству сопоставима либо превосходит fine-tuning предобученных
  языковых моделей при том, что не требует GPU.
- Если захочется добавить дообучение трансформера (например, DistilBERT)
  как дополнительный источник сигнала — это отдельный третий файл/этап,
  сознательно не включён сюда по требованию минимизировать число файлов
  и не усложнять инфраструктуру (GPU, токенизаторы, время обучения) без
  явной необходимости — классический стилометрический подход уже даёт
  очень сильный результат для этой задачи.
